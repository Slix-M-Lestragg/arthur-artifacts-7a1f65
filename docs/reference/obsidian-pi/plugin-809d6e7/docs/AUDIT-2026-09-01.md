# obsidian-pi audit — 2026-09-01

Method: 9 parallel read-only audit lanes over the plugin (`src/`, docs, tests, packaging) plus cross-reference lanes against `pi-ahp-server` (both the canonical tree and the live `feature/farm-view-server` worktree) and the `pi-ahp-client` extension. Every finding carries file:line evidence. Plugin version at audit time: 0.4.0.

## Executive summary

The codebase is lifecycle-conscious and well-tested at the core (28 test suites, `strict: true` TS, zero `@ts-ignore`, zero TODO/FIXME comments), but sags under three structural problems:

1. **A dead generation of features was never deleted** — the RPC/ChatView era (~1.5–2k lines) survives as unreachable code, stale docs, and dead settings.
2. **The same concerns are re-implemented 3–5×** — reconnect state machines, status decoders, formatters, constants (`'0.3.0'` ×12 across two repos, `'ws://localhost:4500'` ×5).
3. **The AHP wire contract is trusted, not verified** — blind `JSON.parse(...) as T` in every transport, error codes sniffed by regex on formatted strings, and one notification family the broker never sends (root cause of known Farm View UI bugs).

## 1. Cross-component findings (broker ↔ plugin ↔ extension)

Highest stakes — these produce live user-visible bugs.

### 1.1 Farm View wire contract (obsidian-pi ↔ pi-ahp-server)

| # | Finding | Flag |

| 2 | **Reconnect snapshots discarded.** Server DOES snapshot `state.chats` on reconnect when root is subscribed (server.ts `handleReconnect` ~2580–2660, `buildSnapshot` ~3000), but client `resumeFromReconnect` explicitly ignores session snapshots ("Defensive: no cached session state", AhpClient.ts:~614–660). 1+2 = empty subagent rows after reconnect. | MISMATCH |
| 3 | **Terminal subscriptions never restored on reconnect.** Client re-subscribes only root/session/chat (AhpClient.ts:415–421); server drops all WS-scoped subs on disconnect. Open AHP terminals silently stop streaming after any broker blip. | MISMATCH |
| 4 | **Shared-client disposal on create failure.** `newHostedAhpSession` catch path disposes the process-wide `ahpClient` (src/main.ts:1950–1955) that FarmView subscriptions point at → catalogue silently dies. | 5 | **Error-code surface by regex.** Server overloads `-32000` (no node-pty / hosted-spawn failure / PTY-not-running ack); client sniffs `/-32000/` on the formatted message string (src/main.ts:1748, 1865). ### 1.2 Extension cross-drift (pi-ahp-client ↔ obsidian-pi)

- **4 divergent AHP client implementations** — pi-ahp-client `ahp-client.ts`, obsidian-pi `AhpClient`, `HostAgentClient`, `swarmDispatch.ts`'s private `BrokerClient`. Different reconnect strategies (extension: none in-client, LiveMirror supervisor 3-attempt re-create w/ echo-cursor clientSeq resume; obsidian: 10-attempt exponential backoff + broker `reconnect` resume endpoint that the extension NEVER uses). Different exactly-once cursors (echo-count vs monotonic-serverSeq dedup). Split error-code coverage: extension handles `-32003`/`-32002` at 10 sites; obsidian handles only `-32000`.
- **Protocol version `'0.3.0'` duplicated 12×** across both repos (pi-ahp-client: live-mirror.ts:132,361, pty-supervisor.ts:124, import-sessions.ts:232, archive-hook.ts:194,309, ahp-client.ts:212; obsidian-pi: AhpClient.ts:172, HostAgentClient.ts:39, swarmDispatch.ts:57+229, main.ts:1722).
- **Title contract drift.** The extension learned the broker ignores `createSession`'s title param and now dispatches authoritative `session/titleChanged` post-create (live-mirror.ts:188–191); obsidian-pi still relies on the ignored param (main.ts `newHostedAhpSession`). FarmView's subagent nesting falls back on title regex `/^[a-z]+: /i` (FarmView.ts:636) which only matches because the extension's `AHP_SESSION_TITLE` env convention feeds it. The extension's 2 stale title-env tests (61/63 pass) are this drift, fossilized.
- **Timeouts diverge**: extension 5s connect/10s request vs obsidian 30s/30s — same operation fails on one client and hangs on the other.
- **Two parallel external-terminal registration conventions**: extension's `terminal/registerExternal` action vs obsidian's `hostAgent.syncInstances` RPC, converging on the same server.
- **Two parallel read paths**: extension's `/ahp` TUI browser reads only local JSONL archives; obsidian's FarmView reads only the server catalogue — broken-mirror (`serverSeq=0`) sessions visible in one UI, invisible in the other.
- Terminal URI scheme-swap convention MATCHES both ways (`ahp-terminal:/` ↔ `ahp-session:/`); subagent chat-id composition MATCHES.

## 3. State/lifecycle solidity

Codebase is unusually lifecycle-conscious overall (deferred-leaf handling, menubar self-healing, in-flight dedup for AHP/auth-bridge). Residual risks:

**Leaks/races (high)**
1. `ensureAhpCatalogConnection` skips disposing a `'connecting'` client (main.ts:1711), but auto-reconnect also sets `'connecting'` (AhpClient.ts:393) → orphaned reconnect-loop client, double "Reconnected" notices.
2. `RpcClient.connect()` returns a resolved promise while connecting (RpcClient.ts:229–232) and `connectRpc` has no in-flight guard → racing reconnects spawn orphaned pi subprocesses.
3. AhpClient's 30s WS open-timeout timer never cleared on success (AhpClient.ts:344–350) — stale timer can close the NEXT socket.
4. `HostAgentClient.dispose()` awaits `hostAgent.unregister` up to 30s → `onunload` can stall.
5. `InstanceManager.dispose()` doesn't await PTY kills (InstanceManager.ts:379–382) → children outlive the plugin on unload.
6. Menubar stop-during-election and close-time double re-election races (MenubarCoordinator.ts, MenubarIpc.ts:301) — transient duplicate trays, self-healing via registry.
7. Unhandled-rejection sites: `void this.startHostAgentClient()` (main.ts:338), vault rename handler (main.ts:320–322), `startMenubar` dynamic import.

**AHP identity state in one plugin-level slot while N leaves exist** — `ahpSessionTitle`/`ahpTerminalUri`/`ahpTerminalMode`/`ahpInitial*`/`ahpCounter` (main.ts:139–152) overwritten per open → the known `ahp-remote-N` vs `ahp-remote` binding bug (main.ts:1870 registers vs :1036 binds), wrong tab titles with multiple sessions, id collisions after counter reset (:931). `unregisterAhpInstance` never detaches open AHP leaves (:927–937) → zombie views.

Positive: `registerEvent`/`registerDomEvent` discipline consistent; menubar timers cleared; PromptPopout temp listeners cleaned; AuthBridge SIGTERM→SIGKILL escalation with cleared timers; menubar-registry destroy-if-current protocol genuinely well-defended.

## 4. Type safety & config security

- **HIGH — Plaintext bearer tokens in `data.json`**: `ahpServerToken` (types.ts:190), `sttToken` (:224) written verbatim via `saveSettings()` (main.ts:1264); read straight into `Authorization: Bearer` headers. Gitignored but unencrypted. (ANTHROPIC key is correctly memory-only, `runtimeApiKey`.)
- **MEDIUM — Settings never validated at load**: shallow `Object.assign` (main.ts:1260); corrupted/hand-edited data.json flows into typed fields unchecked.
- **MEDIUM — All wire data blind-cast**: `JSON.parse(raw) as ...` in AhpClient.ts:473, PtyClient.ts:386, JsonRunner.ts:96, AuthBridge.ts:300, swarmDispatch.ts:153–170. Malformed JSON caught; wrong-SHAPED JSON trusted. No schema/guard layer anywhere.
- TS posture otherwise solid: `strict: true`, zero `@ts-ignore`, ~15 `any` concentrated at Electron/Obsidian boundaries, wire payloads typed `unknown` in protocol types. `types.ts` (settings) vs `types/rpc.ts` (wire) cleanly disjoint.
- Binary surface safe: `shellWhich` injection-guarded (binary.ts:249–262), `execFile` used, vendored node-pty paths plugin-relative.

## 8. FIX SLICE H — prefer-local routing (2026-09, post-audit)

**Gap.** The prefer-local shortcut (open an own-device `ext-<device>-<instanceId>` row as a
local PTY with session resume instead of relaying through the broker) lived only inside
`FarmView.openSession`. The shared attach entry `openAhpTerminalForSession` (used by the
`AhpSessionBrowserModal` picker and FarmView's fallback) had no locality check, so opening
a session published by THIS machine's host agent from the browser self-relayed the local
PTY back through the broker loop — live-mirror confirm, WS subscribe, relayed scrollback.

**Fix.**
- New pure module `src/transport/localRelay.ts`: `parseLocalRelayUri(resource, deviceName)`
  (URI → `{device, instanceId} | null`, case-insensitive, prefix-guarded so `ext-voyagerX`
  ≠ `ext-voyager`) + `matchLocalRelaySession(session, deviceName)` (handles relay rows with
  no `hostAgentName` and external rows whose host name matches the local device).
- `main.ts` gains `openLocalInstanceWithResume(instanceId, sessionTitle?)` (the local-open +
  resume sequence extracted verbatim from FarmView) and desktop-gated
  `openLocalRelaySessionIfLocal(session): boolean` — matches via the shared helper, requires
  `instanceManager.get(instanceId)` to still resolve, then opens locally and returns true.
- `openAhpTerminalForSession` calls it FIRST (before the connected-client check, the
  live-mirror confirm, or any subscribe). The M4 `hostOnline === false` offline gate moved
  into it AFTER the prefer-local check: true-remote offline externals stay blocked with the
  host-offline notice, while own-device rows route locally fine (a local PTY needs no host
  agent online).
- `FarmView.openSession` is now a pure delegation to `plugin.openAhpTerminalForSession` —
  one open path for every surface; the view keeps only the local-mirror badge (via the
  shared helper + instance resolution).
- `AhpSessionBrowserModal` takes the device name and renders an `is-local` badge on
  own-device rows (URI match, mirroring FarmView's `pi-farm-local-mirror-badge`).

**Preserved.** True-remote external rows still attach via AHP; own-device rows whose
instance no longer resolves (renamed/deleted instance) fall through to AHP attach; the
offline gate for remote externals; hosted sessions untouched.
